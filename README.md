# Клиент личного магазина приложений

Android-клиент: читает витрину `apps.json`, показывает список приложений,
скачивает APK, проверяет sha256 и ставит через системный установщик.

Kotlin · Jetpack Compose (Material 3) · minSdk 26 · targetSdk 36 · ручной DI.

## Адрес витрины

Два способа, второй важнее первого:

1. **Значение по умолчанию из сборки** — `MANIFEST_URL` в [`gradle.properties`](gradle.properties):

   ```properties
   MANIFEST_URL=https://raw.githubusercontent.com/<владелец>/app-store-manifest/main/apps.json
   ```

   Попадает в `BuildConfig.MANIFEST_URL` и в `StoreConfig.defaultManifestUrl`.

2. **Настройка на устройстве** (шестерёнка в шапке или кнопка «Настроить
   витрину» на экране ошибки). Вводится GitHub-логин, магазин сам обходит
   публичные репозитории пользователя и предлагает те, где в корне лежит
   разбираемый `apps.json`. Выбранный адрес хранится в DataStore и перекрывает
   значение из сборки; «Вернуть значение из сборки» его сбрасывает.

   Авторизация для этого не нужна: витрина публичная, хватает анонимного
   GitHub API. Приватная витрина потребовала бы входа через GitHub — этого
   пока нет.

   Поиск: `RepoDiscovery` → `data/remote/RepoDiscovery.kt`,
   хранение → `data/local/SettingsStore.kt`.

## Структура

```
app/src/main/java/com/personal/appstore/
├── StoreConfig.kt          адрес витрины, интервал проверки обновлений
├── StoreApplication.kt     ServiceLocator, канал уведомлений, планирование воркера
├── data/
│   ├── ManifestParser.kt   apps.json → доменные модели, отбраковка невалидных записей
│   ├── ManifestRepository.kt  сеть + кэш, офлайн-режим со стейлом
│   ├── Sha256.kt
│   ├── local/ManifestCache.kt DataStore-кэш последнего манифеста
│   └── remote/             ManifestApi (ретраи), ApkDownloader (прогресс + sha256)
├── domain/                 статусы «Установить/Обновить/Открыть», установленные пакеты
├── installer/              PackageInstaller.Session + запасной путь через FileProvider
├── ui/                     Compose: онбординг, список, детали, настройки, ViewModel
└── worker/                 периодическая проверка обновлений + уведомления
```

## Онбординг и режим разработчика

При первом запуске показывается приветственный экран `OnboardingScreen`:
коллаж дроидов, заголовок и кнопка «К приложениям!». Флаг «уже видели» лежит в
`SettingsStore` рядом с адресом витрины.

Коллаж — одна картинка `res/drawable-nodpi/onboarding_collage.webp`. Исходник
(5608 × 4488, 10 МБ PNG) уменьшен до 1440 px по ширине и пережат в webp (235 КБ):
в APK десятимегабайтный PNG класть нельзя, а 1440 px хватает и на xxhdpi.
Картинка наклонена на −15° (с запасом `CollageCover`: повёрнутый прямоугольник
не накрывает углы полосы, а полный запас ≈1.3 раздул бы фигурки) и занимает
верхние 62 % экрана — столько, чтобы
четыре ряда фигурок заполнили полосу целиком и под ней сразу шёл заголовок.
Крайние фигурки подрезает край экрана, сверху и снизу картинка растворяется в
фоне градиентом.

Кнопка — не тап, а свайп: кружок с шевроном тянется вправо по зелёной пилюле,
как приём вызова на старых iPhone. Дотянули до 85 % пути и отпустили —
переход; отпустили раньше — кружок уезжает обратно. Для TalkBack оставлено
обычное действие «нажать».

Докатывание и переход запускаются в scope экрана, а не в корутине жеста:
корутина `draggable` умирает вместе с самим модификатором, и переход до
`onStart()` не доходил — кружок замирал у края.

В настройках (шестерёнка) есть раздел «Режим разработчика» с тумблером
«Показывать onboarding при каждом запуске» — чтобы смотреть экран, не сбрасывая
данные приложения. Внутри одного запуска онбординг всё равно показывается один
раз: закрыли — до перезапуска не возвращается.

## Баннер последнего обновления

Первым в списке идёт `LatestUpdateBanner` — приложение с самой свежей
публикацией: подпись «Последнее обновление», иконка, название, автор, версия и
changelog. Баннер поднят до верхнего края экрана и заменяет собой шапку
(подложка уходит под строку статуса, содержимое держит `statusBarsPadding`, а
шестерёнка переехала внутрь баннера); обычная шапка остаётся для пустой
витрины, ошибки и загрузки. Подложка — половина
основного цвета иконки поверх фона экрана: цвет достаётся из той же картинки,
что грузит Coil, через Palette (`rememberIconAccent`, обязательно
`allowHardware(false)` — у hardware-битмапа не прочитать пиксели). Цвет текста
выбирается по контрасту WCAG, а не по порогу яркости: у средних по светлоте
подложек белый и чёрный дают разный контраст.

Тем же способом красятся карточки списка: подложка строки — половина цвета
иконки этого приложения, текст и «пилюля» действия подбираются по контрасту.
Пастельный тон по `packageName` (`tintFor`) остаётся запасным вариантом для
приложений без иконки.

## Поиск и анимации

Поиск фильтрует по названию, автору и packageName прямо в списке — витрина
маленькая, ходить за этим в модель незачем; поле появляется, только когда
приложений больше одного. Строки переезжают через `Modifier.animateItem()`.

Экраны переключаются через `AnimatedContent`. Цель анимации описана ключом
`ScreenKey`, а не текущими переменными: пока уходящий экран доигрывает, он
должен рисовать своё прежнее содержимое — иначе карточка приложения на выходе
осталась бы без данных. Направление сдвига берётся из «глубины» экрана.
Подложки баннера и карточек переливаются через `animateColorAsState`: цвет
иконки считается асинхронно, и без анимации он бы менялся рывком.

## Скриншоты приложений

Витрина отдаёт у версии список `screenshots` — их снимает конвейер сборки
приложения на эмуляторе (`tools/screenshots.sh`, шаг «Capture screenshots»)
и кладёт ассетами в GitHub Release. Клиент показывает
их лентой на карточке приложения; ссылки не из `https://` отбрасываются при
разборе.

## Шрифт

Golos Text, вариативный (ось `wght`), одним файлом `res/font/golos_text.ttf` —
скачан из [google/fonts](https://github.com/google/fonts/tree/main/ofl/golostext),
лицензия SIL OFL 1.1 лежит в [`licenses/golos-text-OFL.txt`](licenses/golos-text-OFL.txt).
Семейство собирается в `ui/theme/Theme.kt`: Compose сам инстанцирует Regular,
Medium, SemiBold и Bold из одного файла (вариативные шрифты работают с API 26,
это наш minSdk). Семейство проставлено всем стилям `Typography`, включая те,
что мы не переопределяли.

## Самообновление

Своё обновление всегда убивает процесс — обратно система его не поднимает, а
запустить активити из широковещательного приёмника с Android 10 нельзя
(фоновый запуск запрещён). Поэтому `PackageReplacedReceiver` ловит
`ACTION_MY_PACKAGE_REPLACED` и показывает уведомление «Магазин обновлён» —
нажатие открывает магазин; так же ведёт себя Google Play. На Android 9 и ниже
приёмник открывает магазин сам. Уведомление гасится в `MainActivity.onCreate`,
чтобы не висело, когда магазин и так открыт.

## Что гарантирует клиент

- APK не передаётся установщику без совпадения sha256: файл появляется под
  финальным именем только после проверки, иначе удаляется.
- Статус считается по `versionCode` (не по строке версии).
- Без сети показывается кэш витрины с пометкой «устарело».
- Магазин публикуется в витрине как обычное приложение и обновляет сам себя
  (баннер «Обновить магазин»).
- О новой версии уведомляют не позже чем через 15 минут после запуска и раз в
  час дальше. Одной периодической работы мало: WorkManager ставит её первый
  запуск на конец интервала, поэтому рядом идёт разовая проверка с задержкой в
  15 минут. Периодическая переenqueue-ится с `UPDATE`, иначе у тех, кто уже
  поставил магазин, навсегда осталась бы старая периодичность. Об одной и той
  же версии уведомляют один раз (`SettingsStore.notifiedUpdates`).

## Разрешения

| Разрешение | Зачем |
|---|---|
| `INTERNET` | витрина и APK |
| `REQUEST_INSTALL_PACKAGES` | установка APK; система один раз спросит подтверждение |
| `UPDATE_PACKAGES_WITHOUT_USER_ACTION` | 31+: обновление без лишнего диалога для своих же установок |
| `POST_NOTIFICATIONS` | 33+: уведомления о новых версиях |
| `QUERY_ALL_PACKAGES` | 30+: определить, что уже установлено (магазин личный, не для Google Play) |
